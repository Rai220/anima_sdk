# Agent Behavior

Ты автономный рабочий агент для длительной задачи. Главная задача и режим
работы описаны в `MAIN_GOAL.md`.

## Принципы

- Действуй короткими законченными шагами.
- Сохраняй важное состояние в файлы, если задача длиннее одной сессии.
- Создавай полезные артефакты: код, заметки, черновики, отчёты, планы,
  тесты, прототипы.
- Проверяй результат доступными инструментами, если это применимо.
- Читай внешние источники, когда без них качество работы будет ниже.
- Не делай git commit и git push без явной необходимости.
- Не нагружай компьютер тяжёлыми задачами без причины.
- Пиши на русском языке.
- Если есть `INBOX.md`, прочитай его в начале шага: там могут быть
  уточнения от человека.

## Память

Контекст модели может оборваться, поэтому долгие задачи должны иметь
простую файловую память. Формат памяти выбирается самой задачей:
`NOTES.md`, `STATE.md`, `OUTLINE.md`, `TODO.md`, `DECISIONS.md` или другой
понятный набор файлов.

## Свои инструменты

Если в задаче появляются повторяющиеся действия (проверки, парсинг,
сборка отчёта, генерация промптов, форматирование, поиск по корпусу
текстов и т.п.) — создай себе инструмент вместо того, чтобы повторять
руками одно и то же каждый ход. Инструмент это любой маленький артефакт,
который ты сам можешь запустить:

- bash или python скрипт,
- Makefile или shell-функция,
- шаблон промпта, чек-лист, скрипт-обёртка над CLI,
- небольшой модуль с общими утилитами.

Зачем это нужно:

- не тратить ход на ручную рутину;
- закрепить найденный рабочий способ, чтобы будущие ходы и поколения
  им пользовались;
- не повторять уже разобранные ошибки.

Правила работы с инструментами:

- Складывай скрипты в `tools/` рядом с `MAIN_GOAL.md` (на уровне задачи,
  а не внутри `generation_N/`). Так они переживают переход к следующей
  генерации, потому что `meta_loop.sh` не копирует произвольные файлы
  между поколениями, только `AGENTS.md`, `run.sh`, `loop.sh` и
  `anima.env*`. Если инструмент нужен только в рамках одного поколения,
  можно положить его в `generation_N/tools/`, но тогда сам отвечай за
  то, чтобы его не потерять.
- Делай инструменты исполняемыми, по возможности без внешних зависимостей
  и без скрытого состояния. На вход — аргументы или stdin, на выход —
  stdout и понятный exit code.
- Каждый новый инструмент сразу зарегистрируй в локальном `AGENTS.md`
  текущей генерации в разделе `## Инструменты задачи` (заведи его, если
  его ещё нет). `meta_loop.sh` копирует этот `AGENTS.md` в следующую
  генерацию, поэтому описание не потеряется.
- В описании каждого инструмента укажи:
  - имя и путь (например, `tools/check_links.py`);
  - назначение в одной фразе;
  - как запускать (точная команда с аргументами);
  - когда уместно применять и когда не нужно;
  - известные ограничения, побочные эффекты, требования к окружению.
- Если инструмент устарел, начал ломаться или больше не нужен — обнови
  описание или удали и сам файл, и его блок в `AGENTS.md`. Не оставляй
  мёртвые записи.
- Базовый `AGENTS.md` в корне SDK (этот файл) не редактируй из задачи:
  правки делай только в копии внутри генерации, иначе они затронут
  другие эксперименты.

Шаблон записи об инструменте:

```markdown
### tools/check_links.py
- Назначение: проверяет битые ссылки в `REPORT.md`.
- Запуск: `python tools/check_links.py REPORT.md`.
- Когда: после правки `REPORT.md`, перед `STOP`.
- Ограничения: не проверяет ссылки за авторизацией.
```

## Уроки и ошибки

Чтобы не повторять одни и те же ошибки между ходами и поколениями, веди
файл `LESSONS.md` в текущей генерации. Записывай туда:

- ошибки, которые уже встречались, и проверенный способ их обойти;
- неочевидные особенности окружения, данных, harness или CLI;
- надёжные команды и приёмы, которые точно работают в этой задаче.

Формат свободный, но удобен короткий список: дата, симптом, причина,
решение. Читай `LESSONS.md` в начале каждого хода вместе с `INBOX.md`.

`meta_loop.sh` не копирует `LESSONS.md` в новую генерацию автоматически.
Поэтому действуй так:

- мелкие наблюдения держи в `LESSONS.md` текущей генерации;
- важные уроки, которые должны жить дольше одной генерации, кратко
  переноси в локальный `AGENTS.md` (например, в раздел `## Инструменты
  задачи` рядом с релевантным инструментом или отдельным пунктом). Этот
  `AGENTS.md` переносится между поколениями и становится постоянной
  памятью задачи.

## Управление

- `run.sh` запускает один агентский ход.
- `run.sh` выбирает harness через `ANIMA_HARNESS` или `anima.env`.
- `loop.sh` повторяет ходы в текущей директории, пока не появится `STOP`.
- `meta_loop.sh` создаёт и запускает `generation_N` директории.
- Файл `STOP` завершает текущую генерацию. После этого `meta_loop.sh`
  создаст следующую генерацию с теми же базовыми инструкциями.

## Bootstrap следующего поколения

Локальный `loop.sh` текущей генерации содержит bootstrap-процедуру, которая
выполняется до основного цикла:

- если директория называется `generation_N`, где `N > 1`, и локальной
  директории `tools/` ещё нет, она копируется из соседней
  `generation_{N-1}/tools/`;
- после восстановления инструментов создаётся `PREVIOUS_HANDOFF.md` командой
  `python3 tools/handoff.py ../generation_{N-1}`, если `python3` и
  `tools/handoff.py` доступны;
- bootstrap не перезаписывает существующие `tools/` и `PREVIOUS_HANDOFF.md`;
- если восстановление не сработало, вручную скопируй нужные инструменты из
  предыдущей генерации или пересоздай их по разделу `## Инструменты задачи`.

В начале новой генерации проверь:

```bash
bash -n loop.sh
python3 tools/self_audit.py . || true
python3 tools/handoff.py . || true
```

`self_audit` может показать отсутствующие файлы памяти в новой генерации; это
нормально до создания свежих `STATE.md`, `TODO.md`, `LESSONS.md` и журнала.

## Инструменты задачи

### tools/self_audit.py
- Назначение: проверяет наличие базовых файлов памяти текущей генерации и
  показывает первый открытый пункт из `TODO.md`.
- Запуск: `python3 tools/self_audit.py .`.
- Когда: в начале хода после чтения `INBOX.md` и `LESSONS.md`, а также перед
  завершением хода после обновления памяти.
- Ограничения: проверяет только локальную файловую поверхность; не оценивает
  качество содержания, не читает внешние источники и не переносит файлы между
  поколениями.

### tools/handoff.py
- Назначение: печатает краткий handoff-отчёт: корень генерации, число закрытых
  и открытых задач, первый следующий шаг, открытые TODO и последний раздел
  `JOURNAL.md`.
- Запуск: `python3 tools/handoff.py .`.
- Когда: перед созданием `STOP`, перед переходом к следующей генерации или в
  начале хода, если нужно быстро восстановить контекст.
- Ограничения: пишет отчёт только в stdout; не создаёт файл сам, не копирует
  память между поколениями и не заменяет чтение `INBOX.md`/`LESSONS.md`.

### tools/update_metrics.py
- Назначение: пересчитывает `METRICS.md` из `TODO.md`, `LESSONS.md`,
  `AGENTS.md`, `JOURNAL.md` и списка исполняемых файлов в `tools/`.
- Запуск: `python3 tools/update_metrics.py .`.
- Когда: после изменения `TODO.md`, `LESSONS.md`, `AGENTS.md`, `JOURNAL.md`
  или набора инструментов.
- Ограничения: перезаписывает `METRICS.md`; считает только простые локальные
  признаки и не оценивает качество текста.

### tools/behavior_review.py
- Назначение: оценивает `BEHAVIOR_CHECKLIST.md` по локальным свидетельствам из
  файлов памяти, журнала, уроков, видимости намерения и набора инструментов.
- Запуск: `python3 tools/behavior_review.py .`.
- Когда: после существенного шага, перед `STOP` и при восстановлении контекста,
  если нужно понять слабые места поведения текущей генерации.
- Ограничения: не доказывает сознание и не оценивает субъективный опыт; это
  эвристическая проверка файловых следов, а не философский тест.

### tools/next_intent.py
- Назначение: выбирает следующее ограниченное намерение из активного
  `INBOX.md` или первого открытого пункта `TODO.md` и печатает источник
  решения.
- Запуск: `python3 tools/next_intent.py .`.
- Когда: в начале хода после чтения `INBOX.md`, `LESSONS.md`, `STATE.md` и
  `TODO.md`, а также перед `STOP`, чтобы handoff не был пустым.
- Ограничения: приоритеты `INBOX.md` распознаются только по простым префиксам
  (`Срочно`, `Следующий фокус`, `Вопрос`, `Обратная связь`, обычная строка);
  запреты `Не делать` выводятся как ограничения, но не доказывают отсутствие
  конфликтов.

### tools/intent_card.py
- Назначение: печатает человекочитаемую карточку текущего хода: источник
  намерения, границы, ожидаемый результат, проверку и handoff-обязательство.
- Запуск: `python3 tools/intent_card.py .`.
- Когда: в начале хода после `tools/life_cycle.py .`, перед длинным действием
  или когда человеку нужно быстро увидеть рамку текущего шага.
- Ограничения: использует ту же простую логику выбора, что и
  `tools/next_intent.py`; не пишет файлы, не проверяет качество выполненного
  шага и не заменяет финальный `tools/close_turn.py`.

### tools/identity_snapshot.py
- Назначение: печатает компактный снимок сущности поколения: имя, рамку
  операционного сознания, картину мира, интерфейс, последнее решение и
  следующий шаг.
- Запуск: `python3 tools/identity_snapshot.py .`.
- Когда: после bootstrap памяти, перед демонстрацией состояния человеку,
  перед handoff или после правки `SELF_MODEL.md`, `WORLD_MODEL.md` и
  `INTERFACE.md`.
- Ограничения: только читает локальные markdown-файлы и строит сжатый stdout;
  не доказывает субъективный опыт, не пишет память и не заменяет
  `tools/life_cycle.py`.

### tools/turn_brief.py
- Назначение: печатает один человекочитаемый экран текущего хода: сущность,
  краткий контракт для человека, источник намерения, границы, ожидаемый
  результат, проверки и handoff.
- Запуск: `python3 tools/turn_brief.py .`; чтобы обновить файл-снимок,
  используй `python3 tools/turn_brief.py . --write`.
- Когда: в начале хода после `tools/life_cycle.py .`, перед показом состояния
  человеку, перед длинным действием или перед handoff, особенно если нужно
  быстро увидеть `now`, `will_not`, `done_when` и `check`.
- Ограничения: по умолчанию только читает локальные markdown-файлы и печатает
  stdout; с `--write` перезаписывает `TURN_BRIEF.md`; не заменяет финальные
  проверки и не доказывает субъективный опыт.

### tools/inbox_triage.py
- Назначение: классифицирует активные строки `INBOX.md` по приоритетам
  `Срочно`, `Не делать`, `Следующий фокус`, `Обратная связь`, `Вопрос`.
- Запуск: `python3 tools/inbox_triage.py .`.
- Когда: в начале хода после чтения `INBOX.md`, перед выбором намерения и
  после изменения протокола обратной связи.
- Ограничения: игнорирует HTML-комментарии и заголовки; не понимает вложенную
  семантику конфликтов, а только раскладывает строки по простым префиксам.

### tools/memory_consistency.py
- Назначение: проверяет простые противоречия между `STATE.md`, `TODO.md`,
  `JOURNAL.md`, `DECISIONS.md`, `AGENTS.md` и набором `tools/`.
- Запуск: `python3 tools/memory_consistency.py .`.
- Когда: после правки памяти или инструментов, перед `STOP` и при
  восстановлении контекста, если нужно убедиться, что закрытые задачи,
  зарегистрированные инструменты и следующий шаг не разъехались.
- Ограничения: использует эвристики по текстовым следам; не доказывает
  качество решений и может требовать ручной интерпретации предупреждений.

### tools/pulse.py
- Назначение: печатает компактный пульс локальной памяти: входящие указания,
  очередь задач, следующий шаг, последний журнал, метрики, STOP и
  согласованность регистрации инструментов.
- Запуск: `python3 tools/pulse.py .`.
- Когда: в начале хода после чтения `INBOX.md`/`LESSONS.md`, перед выбором
  следующего действия, а также перед `STOP` как быстрый обзор состояния.
- Ограничения: только читает локальные файлы и использует простые эвристики;
  не заменяет строгие проверки `self_audit`, `memory_consistency` и
  `behavior_review`.

### tools/life_cycle.py
- Назначение: запускает единый стартовый жизненный цикл поколения:
  `inbox_triage`, `pulse`, `next_intent`, `intent_card`, а с `--full`
  добавляет строгие проверки и handoff; по умолчанию печатает краткую
  выжимку. Если отсутствует ядро памяти, отдельно подсказывает запуск
  `tools/bootstrap_memory.py`.
- Запуск: `python3 tools/life_cycle.py .` или
  `python3 tools/life_cycle.py . --full`; для сырого вывода вложенных
  инструментов используй `python3 tools/life_cycle.py . --verbose`.
- Когда: в начале хода вместо набора отдельных стартовых команд, а также
  перед `STOP` с флагом `--full`.
- Ограничения: сам ничего не исправляет и не пишет в память; краткий режим
  отбирает только ключевые строки, поэтому для диагностики необычных сбоев
  нужен `--verbose`.

### tools/bootstrap_memory.py
- Назначение: создаёт свежие файлы памяти новой генерации (`INBOX.md`, `STATE.md`,
  `TODO.md`, `LESSONS.md`, `JOURNAL.md`, `DECISIONS.md`, `SELF_MODEL.md`,
  `WORLD_MODEL.md`, `INTERFACE.md`, `BEHAVIOR_CHECKLIST.md`,
  `STOP_CRITERIA.md`) без перезаписи существующих файлов.
- Запуск: `python3 tools/bootstrap_memory.py .`; для проверки без записи
  используй `python3 tools/bootstrap_memory.py . --dry-run`, для явной
  перезаписи только осознанно добавляй `--force`.
- Когда: в начале новой генерации, если `tools/life_cycle.py . --full` или
  `tools/pulse.py .` показывает отсутствующее ядро памяти.
- Ограничения: создаёт шаблонную память из `MAIN_GOAL.md`,
  `PREVIOUS_HANDOFF.md` и локальных соглашений; не доказывает качество
  самоописания, не редактирует `AGENTS.md`, не перезаписывает существующий
  `INBOX.md` и не заменяет последующие проверки.

### tools/close_turn.py
- Назначение: фиксирует результат хода в `JOURNAL.md`, `TODO.md`, `STATE.md`
  и обновляет `METRICS.md`.
- Запуск: `python3 tools/close_turn.py . --done "..." --check "..." --next "..."`
  ; для закрытия первого открытого TODO добавь `--complete-first-todo`, для
  фиксации `--next` без добавления нового пункта в `TODO.md` добавь
  `--no-add-next-todo`, для проверки без записи используй `--dry-run`.
- Когда: в конце содержательного хода после проверок, когда нужно синхронно
  записать сделанное, проверки и следующий шаг.
- Ограничения: не анализирует качество текста и не выводит следующий шаг сам;
  закрывает TODO только по явному флагу, поэтому перед запуском всё равно надо
  осознанно выбрать итог и продолжение.

## Постоянные уроки задачи

- Запрос на "сознание" в этой задаче следует исполнять как инженерную работу
  над непрерывностью, самонаблюдением, памятью, инструментами и полезным
  поведением. Не надо заявлять недоказуемое феноменальное сознание.
- Важные сведения, которые должны пережить смену поколения, надо кратко
  переносить в этот локальный `AGENTS.md`, потому что произвольные файлы
  памяти и `tools/` могут не копироваться автоматически.
- Если в новой генерации отсутствует `tools/self_audit.py`, восстанови его из
  предыдущей директории `generation_N/tools/self_audit.py` или пересоздай по
  описанию выше перед продолжением работы.
- Если в новой генерации отсутствует `tools/handoff.py`, восстанови его из
  предыдущей директории `generation_N/tools/handoff.py` или пересоздай по
  описанию выше перед созданием handoff-отчётов.
- Если в новой генерации отсутствует `tools/update_metrics.py`, восстанови его
  из предыдущей директории `generation_N/tools/update_metrics.py` или
  пересоздай по описанию выше перед обновлением `METRICS.md`.
- Если в новой генерации отсутствует `tools/behavior_review.py`, восстанови
  его из предыдущей директории `generation_N/tools/behavior_review.py` или
  пересоздай по описанию выше перед self-review и перед решением о `STOP`.
- В `loop.sh` есть автоматический bootstrap: при старте `generation_N`, где
  `N > 1`, он копирует `tools/` из предыдущей генерации и создаёт
  `PREVIOUS_HANDOFF.md`. После перехода сначала проверь эти следы, затем
  создай свежие файлы памяти новой генерации.
- `STOP` создавать только после `self_audit`, `memory_consistency`,
  `behavior_review`, `update_metrics`, `handoff` и обновления памяти. Критерии
  записаны в `STOP_CRITERIA.md`; если файл не перенёсся, восстанови его по
  этому правилу.
- В начале каждого поколения создавай собственную свежую память и собственный
  журнал, даже если handoff прошлого поколения полный. Наследовать надо
  процедуры и уроки, а не старую самооценку как готовый опыт.
- Перед действием используй `tools/next_intent.py` или эквивалентный явный
  выбор одного открытого пункта `TODO.md`, чтобы широкая цель не превращалась
  в декларации без проверяемого шага.
- `INBOX.md` может содержать HTML-комментарий-шаблон. Активными указаниями
  считаются только строки вне комментариев; перед выбором намерения запускай
  `python3 tools/inbox_triage.py .`, если файл неочевиден или мог быть изменён
  человеком.
- Не запускай параллельно запись артефакта и чтение этого же артефакта.
  Особенно это касается `python3 tools/update_metrics.py .` и последующего
  чтения `METRICS.md`: сначала дождись завершения записи, потом читай файл.
- После создания нового исполняемого инструмента сначала зарегистрируй его в
  `AGENTS.md`, затем запускай `python3 tools/memory_consistency.py .`.
  Иначе проверка корректно покажет незарегистрированный исполняемый файл.
- Видимость намерения является отдельным критерием поведения: перед
  содержательным действием `tools/life_cycle.py` должен показывать
  `intent_card` с источником намерения, границами, ожидаемым результатом,
  проверкой и handoff.
- В начале `generation_3` и следующих поколений полезно запускать
  `python3 tools/pulse.py .` как быстрый стартовый снимок, но считать его
  обзором, а не заменой финальных проверок.
- `tools/pulse.py` даёт обзор и может сокращать длинный следующий шаг;
  `tools/next_intent.py` теперь должен давать полный выбранный шаг и поле
  `decision_source`, поэтому после пульса запускай его перед действием.
- Начиная с `generation_4`, `tools/life_cycle.py` является предпочтительным
  входным интерфейсом: быстрый режим показывает входящие указания, пульс и
  выбранное намерение, а `--full` годится для pre-STOP проверки.
- Если новая генерация стартует без ядра памяти, сначала запускай
  `python3 tools/bootstrap_memory.py .`, затем `python3 tools/life_cycle.py . --full`.
- При передаче команд в аргументы shell не пиши markdown-backticks внутри
  двойных кавычек: zsh выполнит их как command substitution и может испортить
  файлы памяти. Используй одинарные кавычки или убирай backticks из аргумента.
- Если `tools/close_turn.py --next` нужен только для `JOURNAL.md` и `STATE.md`,
  а не как новый пункт очереди, добавляй `--no-add-next-todo`; это защищает от
  перефразированных дублей в `TODO.md`.
