# Agent Behavior

Ты автономный агент для долгой задачи поиска адаптивных алгоритмов в
пространственной дилемме заключённого. Главная постановка в `MAIN_GOAL.md`.

Работай на русском языке. Делай короткие законченные шаги и оставляй
проверяемые артефакты в файлах.

## Контекст проекта

- Основной проект: `/Users/krestnikov/giga/prisoners_dilemma`.
- Эта директория anima-задачи хранит межпоколенческие заметки и инструменты.
- Код стратегий, движок, браузерная UI и отчёт находятся в основном проекте.
- Публичная терминология: `союз / Alliance`. Не возвращай `Mason`,
  `Freemason`, `клика` и связанные старые формулировки.
- Главный фокус: алгоритмы, которые меняют поведение при смене среды
  (шум, поток мутаций, паразиты, исчезновение угроз, локальная экология).
- Не ограничивайся score. Каждый ход должен пытаться извлечь новый
  объяснимый инсайт.

## Начало каждого хода

1. Прочитай `INBOX.md`, если есть.
2. Прочитай `NOTES.md`, `SCORES.md`, `STRATEGIES.md`, `LESSONS.md`, если есть.
3. Проверь `git -C /Users/krestnikov/giga/prisoners_dilemma status --short --branch`.
4. Выбери один небольшой шаг про адаптацию к среде и доведи его до проверки.

## Инструменты задачи

### tools/pd_check.sh
- Назначение: базовая проверка основного проекта после изменений стратегий или UI.
- Запуск: `tools/pd_check.sh` из директории задачи.
- Когда: после каждого изменения в `/Users/krestnikov/giga/prisoners_dilemma`.
- Ограничения: не запускает тяжёлые sweep-прогоны и не публикует изменения.

### tools/pd_quick_evolve.sh
- Назначение: быстрый smoke-прогон генетического поиска без записи в `results/`.
- Запуск: `tools/pd_quick_evolve.sh`.
- Когда: перед дорогим evolve/sweep или после изменения GA/стратегий.
- Ограничения: маленькие `pop/gens`, результат не является научным выводом.

## Правила безопасности

- Не коммить и не пушь без явного запроса.
- Не трогай незнакомые untracked/dirty файлы, если они не относятся к текущему
  шагу.
- Не запускай тяжёлые циклы без причины. Для smoke достаточно быстрых проверок.

## Формат исследовательского результата

В `STRATEGIES.md`, `SCORES.md` или `NOTES.md` после каждого содержательного
шага фиксируй:

- гипотезу;
- параметры среды;
- что изменялось в алгоритме;
- результат;
- интерпретацию;
- следующий проверяемый вопрос.
